# Исследовательская работа по оптимизации вычислений необходимых для построения множества Мандельброта

## Описание
В проекте реализовано построение множества Мандельброта с графической визуализацией.

Поскольку вычисление множества требует значительных вычислительных ресурсов, основной акцент сделан на оптимизации производительности. Были исследованы подходы, позволяющие кратно ускорить вычисления.

Ключевое ускорение достигается за счёт использования SIMD-инструкций (AVX512), которые позволяют обрабатывать несколько значений за одну операцию. Для этого применяются intrinsics — функции, напрямую отображающиеся в инструкции процессора и дающие полный контроль над векторными вычислениями.
 
Работа выполнена на языке **C**, использует графическую библиотеку **TXLib** для визуализации. Собирается при помощи **g++** под **Windows 11**.

Разработка и тестирование велась на процессоре **AMD Ryzen 7 8845H** с поддержкой **AVX512**.

## Построение множества Мандельброта
### Математическая модель 
Множество Мандельброта — это множество точек комплексной плоскости, для которых последовательность, заданная рекуррентным соотношением $$z_{n+1} = z_n^2 + c, \quad z_0 = 0$$ остаётся ограниченной.

### Алгоритм построения  
Для каждой точки **c** на комплексной плоскости:
1. Итеративно вычисляется последовательность $z_n$
2. На каждом шаге проверяется модуль $|z_n|$
3. Если $|z_n| > M$, вычисления прекращаются

    - Если превышение произошло — точка **не принадлежит** множеству
    - Если за **N** итераций превышения не произошло — точка считается **принадлежащей** множеству  

#### Замечания
- Если $|z_n| > M$ достигается раньше, чем за **N** итераций, дальнейшие вычисления для точки прекращаются 
- В реализации использовались значения:
    - **M = 2** — при $|z_n| > 2$ последовательность гарантированно расходится
    - **N = 256** — на практике этого достаточно, чтобы определить принадлежность точки в большинстве случаев

### Графическая визуализация
Для визуализации использовалась библиотека **TXLib**.

#### Инициализация окна и буфера

- Создание окна:
```C
txCreateWindow(WIDTH_WINDOW, HEIGHT_WINDOW);
```   
- Получение указателя на видеобуфер:
```C
videoMemBuffer = txVideoMemory();
```
- Видеобуфер представляет собой двумерный массив пикселей, соответствующий размеру окна. Каждый пиксель хранится в формате **RGBA**:
    - красный (R)
    - зелёный (G)
    - синий (B)
    - прозрачность (A)

Прямой доступ к памяти позволяет значительно ускорить отрисовку.

#### Оптимизация отрисовки

- Для устранения мерцания отключается автоматическое обновление окна:
```C
txLock();
```
- После завершения записи в буфер обновление включается обратно:
```C
txUnlock();
```

- После обработки всех пикселей окно обновляется:
```C
txRedrawWindow();
```

#### Отображение множества
Для каждого пикселя:
- вычисляется поведение последовательности $z_n$
- Цвет определяется числом итераций до превышения порога **M**

### Низкоуровневая оптимизация 
Вычисление множества Мандельброта является вычислительно затратной задачей.  
Даже при компиляции с оптимизацией **-O3** частота обновления изображения составляет всего ~7–8 FPS, что делает интерактивную работу затруднительной.

Это делает оптимизацию критически важной частью реализации.

#### Основная идея 
Ключевая оптимизация основана на использовании **SIMD (Single Instruction, Multiple Data)** - подход при котором одна инструкция обрабатывает сразу несколько элементов данных.
Современные процессоры поддерживают SIMD-инструкции (использовался **AVX-512**), позволяющие выполнять операции над векторами чисел параллельно.

#### Почему это эффективно
Высокая эффективность достигается за счёт аппаратной поддержки:
- Создаются специальные блоки векторных регистров:
    - **SSE**: 128 бит(XMM)
    - **AVX**: 256 бит(YMM)
    - **AVX-512**: 512 бит(ZMM)
- Векторные ALU выполняют операции независимо над каждым элементом регистра (данные обрабатываются как набор чисел, а не как одно большое число)
- Отдельные исполнительные порты для векторных операций
- Наличие специализированных блоков
    - **Shuffle Unit** — для быстрой перестановки битов внутри векторных регистров
    - отдельные исполнительные порты для векторных операций

#### Практический эффект 
В контексте задачи построения множества Мандельброта это позволяет:
- вычислять сразу несколько точек множества параллельно  
- уменьшить накладные расходы на проверки условия в цикле
- значительно повысить загрузку вычислительных блоков процессора

#### Этапы оптимизации
Оптимизация проводилась в несколько этапов:
- скалярная версия — 1 точка за итерацию  
- ручная векторизация — 16 точек (последовательно)
- SIMD (AVX-512) — 16 точек за одну инструкцию 

#### Этап 1: ручная векторизация

На первом этапе была реализована обработка сразу нескольких точек за одну итерацию цикла.

Вместо последовательного вычисления одной точки, данные группируются в массивы размером **UNWRAP_NUMBER = 16**, и все операции выполняются поэлементно.

Пример кода:

```C
float curComplexSquare[UNWRAP_NUMBER] = {0.0f};

for (int i = 0; i < UNWRAP_NUMBER; i++) {
    curComplexSquare[i] = curComplexReSquare[i] + curComplexImSquare[i];
}
```

Несмотря на такую организацию данных, компилятор даже с флагом -O3 не смог автоматически преобразовать данные циклы в SIMD-инструкции.

Тем не менее, за счёт:

- уменьшения накладных расходов на управление циклом
- лучшей локальности данных
- частичной развертки вычислений

производительность увеличилась примерно в **2–2.5 раза**.

#### Этап 2: использование SIMD intrinsics
Для гарантированного использования SIMD-инструкций код был переписан с использованием intrinsic-функций.

Intrinsic-функции — это специальные функции, которые компилятор напрямую транслирует в соответствующие инструкции процессора.

В отличие от вставок `asm`, такой подход:
- сохраняет переносимость кода
- позволяет компилятору выполнять дополнительную оптимизацию
- обеспечивает контроль над используемыми инструкциями

Пример (AVX-512):
```C
__m512 curComplexSquare =
    _mm512_add_ps(curComplexReSquare,
                  curComplexImSquare);
```

Здесь:
-  за одну инструкцию обрабатываются сразу **16** значений (512 бит / 32 бита на float).
- маска `mask` позволяет выполнять обновление только для тех элементов, которые ещё не вышли за пределы множества

#### Результат
Переход от скалярных вычислений к SIMD-инструкциям позволил значительно увеличить производительность.

Для количественной оценки ускорения проведён полноценный тест производительности(см. далее)

### Проведение измерений
#### Итог

Оптимизированная версия (SIMD / AVX512) показывает ускорение:

> **≈ 14.2× быстрее базовой реализации**

#### Условия измерений

Условия соответствуют описанным в предыдущем разделе:

- Количество запусков: **50** (для снижения влияния случайных факторов)
- Разрешение: **800×600**
- Максимальное число итераций: **256**
- 1000 кадров на одно измерение
- Визуализация и сохранение результатов отключены (измеряется только время вычислений)
- Компиляция: **-O3**

Для предотвращения удаления вычислений компилятором (из-за отсутствия побочных эффектов) использовалась «заглушка»:

```C
asm volatile("" :: "v"(exitIndexes));
```
Эта инструкция не генерирует машинный код, но препятствует удалению вычислительного блока компилятором.

#### Метод измерения

Измерение времени выполнялось с использованием функции `QueryPerformanceCounter` из `<windows.h>`.

Функция основана на аппаратном счётчике **TSC (Time Stamp Counter)** и обеспечивает высокую точность измерений (до микросекунд и ниже).
Для перевода значений в секунды использовалась `QueryPerformanceFrequency`.

Для автоматизации обработки измерений:
- нахождения средних значений
- расчета погрешностей
- сохранения результата в удобном **CSV** формате использовалась собственная мини-библиотека(см. **measuresHandler**)
